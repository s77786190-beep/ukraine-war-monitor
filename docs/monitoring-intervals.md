# Интервал мониторинга

## Настройка в приложении

В настройках приложения должен быть пункт «Частота проверки» со следующими вариантами:

- 5 минут
- 10 минут
- 15 минут
- 20 минут
- 30 минут
- 45 минут
- 1 час
- 3 часа
- 5 часов
- 12 часов
- 24 часа

Значение по умолчанию: **30 минут**.

Настройка должна сохраняться после перезапуска приложения. Интерфейс должен показывать выбранный интервал, время последней успешной проверки и время следующей плановой проверки.

## Логика планировщика

GitHub Actions не позволяет надёжно задавать произвольное расписание из пользовательского интерфейса. Поэтому технический workflow запускается с частотой не реже одного раза в 5 минут, читает `config/monitoring.json` и выполняет сбор источников только тогда, когда наступил срок следующей проверки согласно `interval_minutes`.

Поддерживаемые значения интервала: `5, 10, 15, 20, 30, 45, 60, 180, 300, 720, 1440`.

Фактическое время запуска GitHub Actions может задерживаться из-за очереди GitHub. Нельзя показывать пользователю гарантию запуска ровно минута в минуту.

## Требования к реализации

- Изменение интервала в приложении должно обновлять сохранённую настройку планировщика.
- Проверка должна выполняться по умолчанию каждые 30 минут.
- Ошибка одного источника не должна останавливать проверку остальных.
- Фиксировать время последней попытки и последней успешной проверки.
- Не создавать дубликаты новостей при повторных запусках.
- Сохранять прямую ссылку на исходную публикацию и метку времени.
- Различать официально подтверждённую информацию, сообщения СМИ и неподтверждённые сообщения.
- Если источники недоступны, показывать это отдельно от результата «новых сообщений нет».

## Важное техническое замечание

Само наличие расписания GitHub Actions не означает, что сборщик новостей уже реализован или что источники уже подключены. Нужны отдельные модули получения публикаций, нормализации, дедупликации, хранения и API для приложения.
